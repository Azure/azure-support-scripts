# RCA Tool — Leptos 0.8 Web Interface

A pure client-side (CSR) WebAssembly reimplementation of the RCA Tool UI using
[Leptos 0.8](https://leptos.dev/).

## Key Properties

- **No server required** — compiles to static HTML + WASM + JS files
- **Reuses existing JS parsers** — the same Web Worker (`worker.js`) and
  parser modules (`src/parsers/*.js`) run unchanged
- **Stream decompression** — XZ archives are decompressed via the same
  `liblzma-wasm` streaming pipeline
- **Per-parser debug** — pass `?debug` in the URL to enable per-parser
  `console.log` output from the JS worker

## Prerequisites

- Rust 1.75+ with `wasm32-unknown-unknown` target:
  ```bash
  rustup target add wasm32-unknown-unknown
  ```
- [Trunk](https://trunkrs.dev/) 0.21+:
  ```bash
  cargo install trunk
  ```

## Build

```bash
./build.sh            # copies JS assets + runs trunk build
```

Or manually:
```bash
# 1. Copy JS assets (worker, parsers, liblzma-wasm)
mkdir -p assets/parsers assets/liblzma-wasm/dist-streaming
cp ../src/worker.js assets/liblzma-streaming-worker.js
cp ../src/parsers/*.js assets/parsers/
cp ../src/utils.js assets/
cp ../src/performance.js assets/
cp -r ../web/liblzma-wasm/dist-streaming/* assets/liblzma-wasm/dist-streaming/

# 2. Build with trunk
trunk build
```

Output goes to `dist/`.

## Serve Locally

```bash
trunk serve --open     # starts dev server on http://localhost:8090
```

Or serve the `dist/` directory with any static file server.

## Architecture

```
web-leptos/
├── Cargo.toml          # Rust dependencies (leptos 0.8 csr, web-sys, serde)
├── Trunk.toml          # Trunk build config
├── index.html          # Trunk entry point
├── styles.css          # Shared CSS (copied from web/styles.css)
├── build.sh            # Build helper script
├── assets/             # JS runtime files (generated by build.sh)
│   ├── liblzma-streaming-worker.js
│   ├── parsers/*.js
│   ├── liblzma-wasm/dist-streaming/
│   ├── utils.js
│   └── performance.js
└── src/
    ├── main.rs          # App entry point, mounts Leptos to <body>
    ├── types.rs         # Rust types mirroring JS analysis results
    ├── worker_bridge.rs # web_sys::Worker interop (postMessage protocol)
    └── components/
        ├── mod.rs
        ├── theme_toggle.rs   # Dark / Light / Colorblind toggle
        ├── drop_zone.rs      # File upload (drag-and-drop + input)
        ├── progress_bar.rs   # Decompression / parsing progress
        ├── analysis_view.rs  # Routes to section renderers
        └── sections/
            ├── mod.rs
            ├── helpers.rs     # Shared: Section, KvTable, JsonDump
            ├── azure_vm.rs    # Azure VM Properties + Extensions
            ├── cluster.rs     # Cluster Configuration
            ├── distribution.rs # RHUI, FIPS, Leapp, Packages
            ├── events.rs      # Events (OOM, reboot, XFS, SSH, etc.)
            ├── networking.rs   # Interfaces + Firewall
            ├── kernel.rs       # Kernel tuning, time sync, debugfs, vmcore
            ├── storage.rs      # LVM, RAID, BTRFS, fstab, NVMe
            └── archive.rs      # Archive contents summary
```

## How It Works

1. User drops an archive file (sosreport `.tar.xz`, supportconfig, InspectIaaSDisk `.zip`)
2. Leptos reads the file via `FileReader`, detects the format (magic bytes)
3. A `web_sys::Worker` is created pointing to `liblzma-streaming-worker.js`
4. The worker decompresses → parses → posts progress and results back
5. Leptos deserializes the result via `serde-wasm-bindgen` into `AnalysisResult`
6. Reactive components render each section (Azure VM, Cluster, Distribution, etc.)

## Status

This is an initial implementation. Some sections render their data as pretty-printed
JSON (`JsonDump`) rather than full structured tables. The sections that are fully
rendered include:

- Azure VM Properties (key-value tables)
- FIPS Status (6-source table)
- Events (per-category with counts)
- Networking (interface table)
- Archive Contents (file type summary)

All other sections display via `JsonDump` and can be iteratively improved.
